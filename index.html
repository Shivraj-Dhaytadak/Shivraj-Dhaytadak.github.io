The Challenge (Situation & Friction)

14-Day Release Cycle & LLM Compliance Risk

When I joined Allianz Services, insurance claim lodgement was bottlenecked by legacy release cycles and strict regulatory oversight:

  • 3-Week Developer Bottleneck: Modifying business rules or launching a new claim journey required full backend developer refactors, schema re-compilation, and lengthy CI/CD runs.
  • Regulatory Compliance Liability: LLM non-determinism under Australia Corporate Privacy Standards meant any hallucinated policy term or leaked citizen PII could jeopardize operating licensing.
My Mandate: Architect a multi-agent framework that empowers prompt engineers and business analysts to ship new claim journeys in < 24h with zero backend redeployment and verified regulatory compliance.
The Breakthrough (Architecture & Action)

Declarative JSON Engine & LangGraph State Machine

I architected a Declarative JSON Workflow Engine that decoupled prompt configurations, state transition routes, and tool schemas from the execution binary:

  • Declarative GitOps Delivery: Claim specialists author and version entire journeys as single JSON documents in Git — slashing rollout cycles from 3 weeks to under 24 hours.
  • Pre-Screened State Graph: Ingests Kafka and Azure Event Hub streams through Azure Content Safety and LangChain PII redaction, feeding cyclical LangGraph state machines with strict Pydantic runtime typing.
Key Innovation: Pre-compiled AST schema caching in worker RAM + warm Kafka consumer pools to eliminate cold-start latency.

Production Trade-Offs & Bottleneck Mitigations
Trade-Off: AST Schema Parsing

Decoupled JSON schemas added ~15ms cold session overhead during runtime graph compilation.

Mitigation: Pre-compiled AST schemas stored in worker-local LRU cache and warm Kafka pools.
• Amortized parse latency: < 0.4ms
Trade-Off: Kafka Pod Rebalances

In-flight LangGraph state risked mutation loss during horizontal pod autoscaling or broker rebalance events.

Mitigation: Azure Durable Orchestrators commit checkpoint state after every discrete agent reasoning hop.
• Exactly-once delivery guarantee
Trade-Off: PII Redaction vs Latency

LLM-based PII scrubbing added 350ms+ token latency and suffered non-deterministic omissions.

Mitigation: Deterministic regex pre-filter + Azure Content Safety before token generation; strict Pydantic model validation on exit.
• Zero unredacted PII in logs

Core Engineering Principles
PRINCIPLE 01

Determinism Over Luck

LLMs are statistical sequence predictors, not verified state machines. Never allow an LLM to mutate system state without strict Pydantic runtime schema validation. If an agent output fails type boundaries, drop into a deterministic recovery gate immediately.

• Strict Pydantic runtime typing
PRINCIPLE 02

Schema-First Invariants

Every graph node output is strictly bound to typed schemas before downstream dispatch. Prompts and transition routes live in declarative JSON, eliminating backend binary redeployments and ensuring zero unvalidated state drift.

• Decoupled JSON state machine
PRINCIPLE 03

Defensive Sanitization

Sanitize before compute, never after. Pre-model guardrails, Azure Content Safety jailbreak shields, and LangChain PII redactors guarantee that zero untrusted or adversarial payloads reach foundational LLM reasoning layers.

• Zero PII & injection breaches

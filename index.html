The Challenge (Situation & Friction)

14-Day Release Cycle & LLM Compliance Risk

Insurance claim lodgement is legally audited and high stakes. Historically, modifying business lodgement rules or introducing a new insurance claim type required 10–14 days of backend developer engineering, hardcoded validations, schema changes, and full CI/CD deployment cycles.

Furthermore, LLM stochastic non-determinism introduced legal, compliance, and hallucination risks under Australian privacy mandates (APP), requiring strict boundary enforcement.

The Mandate: Enable prompt engineers to launch new claim journeys in < 24h with zero backend redeployment and 100% regulatory compliance.
The Breakthrough (Architecture & Action)

Declarative JSON Engine & LangGraph State Machine

Engineered a Declarative JSON Workflow Engine that completely decouples prompt configurations, state transition routes, and tool schemas from the execution binary. Each claim journey is configured via a single declarative JSON schema document.

Incoming stream payloads from Kafka and Azure Event Hubs are ingested through Azure Durable Functions, filtered by Azure Content Safety and LangChain PII redaction, and orchestrated across LangGraph state machines with runtime Pydantic schema invariants.

Key Innovation: Decoupled prompt AST schemas cached in hot memory + warm Kafka consumer pools to eliminate cold-start latency.

Trade-Off: AST Schema Parsing

Decoupled JSON schemas added ~15ms cold session overhead during runtime graph compilation.

Mitigation: Pre-compiled AST schemas stored in worker-local LRU cache and warm Kafka pools.
• Amortized parse latency: < 0.4ms
Trade-Off: Kafka Pod Rebalances

In-flight LangGraph state risked mutation loss during horizontal pod autoscaling or broker rebalance events.

Mitigation: Azure Durable Orchestrators commit checkpoint state after every discrete agent reasoning hop.
• Exactly-once delivery guarantee
Trade-Off: PII Redaction vs Hallucination

LLM-based PII scrubbing added 350ms+ token latency and suffered non-deterministic omissions.

Mitigation: Deterministic regex pre-filter + Azure Content Safety before token generation; strict Pydantic model validation on exit.
• Zero unredacted PII in logs
Engineering Trade-Off Analysis

Decoupled JSON schemas introduced slight initial parsing overhead (~15ms per cold session). We mitigated this by caching validated AST schemas in hot worker memory and storing policy documents in hot Azure Blob Storage.

Key Architectural Takeaway

Strict runtime Pydantic schema validation at every micro-agent node boundary is 10x cheaper than attempting to debug corrupted multi-agent conversational states downstream in production.
